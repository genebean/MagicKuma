# Compatibility investigation

On 2026-11-24 a GitHub repository-name search for magickuma returned no results. AutoKuma v2.0.0 is the latest non-prerelease. Uptime Kuma 2.5.12 is the stable downstream test target. The default AutoKuma build targets Kuma 2.x, and a separate compile-time feature targets 1.x. MagicKuma targets the default v2 build. The live integration fixture verified this pair on Linux. Both upstream projects use the MIT License. ## Durable state and coordinated reads

Use a single writer per state directory, serialize publications and replace each client's state with a same-directory temp file, fsync, rename and directory fsync. Persist publication freshness independently so retries of identical content do not rewrite definitions. Source corruption must stop generation. Restore from backup rather than interpreting corruption as an empty set.

The receiver publishes one atomically replaced aggregate of generated definitions. A separate supervisor materializes an immutable private static directory per AutoKuma process and gives AutoKuma that literal path. Stop and reap the old reader before switching processes. This isolates client publication from upstream availability and avoids a moving path during a scan. Run the reader under a separate service account with read-only access to the aggregate. Persistent AutoKuma identity mappings outlive process restarts. A downstream outage must never roll back an accepted client snapshot.

Under the history-preserving policy an operator must explicitly pause or retire formerly authorized checks in Kuma. Policy reductions produce a persistent actionable record and degraded readiness until resolved. File deletion alone is insufficient. Automatic destructive removal requires separate design review.
