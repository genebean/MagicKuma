# Threat model

A publishing token authorizes the checks for one namespace. The HTTPS terminator, MagicKuma server administrator, reconciler and Kuma operator are trusted. Isolate the loopback HTTP hop; forwarding plain HTTP across an untrusted network exposes all bearer tokens. Expose the PUT route to publishers. Allow the minimal GET probes from the Kuma network and restrict metrics to the scraper. Gate optional publisher status with the same credential. Avoid proxy request/header/body logging and forward only to the intended listener.

Native policy authorizes canonical literal addresses against CIDRs and canonical DNS names against domain patterns. A domain grant trusts its DNS operator. The receiver performs no DNS lookup. Network ranges grant no additional DNS names and do not constrain the addresses to which allowed names resolve. Use executor-side firewall rules, controlled DNS and egress filtering to enforce allowed addresses at connection time. Cover IPv4, IPv6, link-local, loopback, private services and cloud metadata explicitly. A compromised DNS zone can redirect traffic between submissions. A path on an approved origin can have application-specific effects even for a GET.

Restrict HTTP to approved destinations/ports, GET, validated certificates and zero redirects. Deny userinfo, fragments, proxies, arbitrary headers, credentials, bodies, alternative resolvers and unrecognized properties. Validate every destination a new monitor type uses. Keep browser, MQTT, database and custom request support gated on per-type authorization. No secrets in Nix-generated monitor declarations. Future credential references should be admin-defined opaque names resolved in the runtime directory with an explicit per-client allowlist.

Case folding, trailing dots, ambiguous IPv4 forms, IPv6 zones, mapped addresses and URL parser differences all matter. Keep a small accepted input grammar and test rejection. Limit size, frequency, path syntax, JSON nesting and counts. Treat all AutoKuma template syntax as privileged. Tokens consist of 32 random bytes encoded in base64url. Store hex SHA-256 digests on the server. Distribute files using your secret manager, allow overlapping digests during rotation, then remove the old digest and reload the server. Never put the token in a URL.

State, export and reader working directories must be owned by the corresponding service and writable only by that owner. Configure the parent directories so untrusted local users cannot rename them. The reader needs group read/traverse on the aggregate only. Keep reader program paths absolute and administrator-controlled. Treat the proxy's rate limits, executor egress rules and ownership of those paths as part of the deployment boundary.
